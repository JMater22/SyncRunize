# COMPLETE FLOW ANALYSIS

From Finishing a Run to Creating a Post

## 1. ROUTE CREATION

Entry: useRunTracker.recordRun()
File: Mobile-App/ionic-app/src/hooks/useRunTracker.ts (lines 441-479)

Steps:
- Validates session.status === FINISHED
- Calls buildRoutePayload(session, meta)
- Sends to createRoute(payload) API
- Returns RecordedRouteSummary with routeId, snapshotUrl

Route Payload Contents:
- route_name, visibility, duration_seconds, average_pace
- distance_km, estimated_calories
- chosen_path (GPS array), start_lat, start_lng, end_lat, end_lng
- weight_kg


## 2. BACKEND ROUTE PROCESSING

File: backend/models/user_route_model.js (lines 20-107)

Process:
- Parse chosen_path array
- Calculate distance_km using haversineDistance between GPS points
- Calculate average_pace = (duration_seconds/60) / distance_km
- Calculate estimated_calories = weight_kg * distance_km * 1.036
- Call generateRouteSnapshot(pathArray) -> returns Mapbox URL
- INSERT into user_routes table
- Return route with route_id, snapshot_url, calculated metrics

Stored Fields: distance_km, duration_seconds, average_pace, estimated_calories (all CALCULATED)
snapshot_url is GENERATED by map_snapshot.js

## 3. SNAPSHOT GENERATION

File: backend/utils/map_snapshot.js

generateRouteSnapshot(routePath, options):
- Uses Mapbox Static API (or fallback: Google, OSM, MapTiler)
- Encodes path as GeoJSON LineString with stroke properties
- Adds start marker (blue) and end marker (red)
- Returns complete URL for static map image
- Stored in user_routes.snapshot_url

## 7. DATABASE SCHEMA

USER_ROUTES table:
- route_id (PK), user_id (FK)
- route_name, chosen_path (JSON)
- distance_km (CALCULATED), duration_seconds
- average_pace (CALCULATED), estimated_calories (CALCULATED)
- start_lat, start_lng, end_lat, end_lng
- snapshot_url (GENERATED), visibility, route_status, created_at

POSTS table:
- post_id (PK), user_id (FK), route_id (FK optional)
- content (caption), image_url (snapshot URL)
- visibility, created_at

## 8. REDUNDANCY ISSUE

PROBLEM: deprecated createPostFromRoute() method stores duplicate data

The createPostFromRoute() function (post_model.js:214-259) inserts:
- route_name, distance_km, duration_seconds, average_pace
- estimated_calories, snapshot_url

All of these already exist in user_routes table. This creates:
1. Data duplication
2. Inconsistency risk if route metrics change
3. Storage waste
4. No cascading updates

CURRENT STATUS: Normal flow uses simple createPost() which only sends:
- route_id, content, image_url
This is CORRECT and does NOT create redundancy.

Redundancy only occurs if deprecated createPostFromRoute() is called.

## 9. SNAPSHOT URL DUPLICATION

Snapshot URL stored in TWO places:
1. user_routes.snapshot_url (server-generated, primary)
2. posts.image_url (snapshot sent with post)

Less critical than metric duplication but still inefficient.

13. POST /posts to backend

15. Post appears in community feed

## 12. CRITICAL FINDINGS

2. Snapshots are generated and stored in user_routes.snapshot_url
3. Post creation uses CORRECT minimal approach (no redundancy)

5. Data properly linked via route_id field
